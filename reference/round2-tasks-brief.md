【任務排序建議】
請把以下項目排在較前面：
1. 資料庫 migration（建立 stores、menu_items 表，依 shared-schema 定義）
2. Seed script（測試用店家/餐點假資料）
3. 距離排序的核心運算邏輯（不依賴 UI，可獨立測試）
4. 定位權限請求與拒絕時的替代方案
5. 店家清單/餐點瀏覽的 UI 頁面
排在較後面：
- LIFF 入口限定的判斷邏輯（一般網頁/iOS/Android 不顯示此功能的入口）
  可以晚一點做，先把核心功能在 LIFF 環境跑通再處理入口限制
- 空狀態、定位失敗等邊界情境的畫面，建議在核心流程（拿得到店家清單、
  排得出距離）驗證沒問題後再補

【提醒：migration 檔案先確認一次】
本輪的 migration 是這張表在專案中第一次被建立（本輪負責讀取，但如果
plan.md 規劃的順序是本輪先建表，第三輪之後合併時需要對齊 migration
版本號）。任務清單裡如果包含建立 migration 這項，請在任務描述中提醒：
合併回 main 前，需要跟第三輪分支確認 migration 檔案沒有重複或版本號
衝突，這件事列為合併前的人工檢查項目，不需要 agent 自動處理。

【驗收標準對齊】
每個任務盡量對應 spec.md 裡已經定義好的驗收標準（例如「定位被拒絕時
退回顯示全部店家、不排序」這條，應該有一個對應的任務或至少是某個任務
的驗收條件之一），避免任務清單只涵蓋 happy path、漏掉邊界情境。
